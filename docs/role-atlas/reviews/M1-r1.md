# M1 review, round 1

Reviewer checks run: the full suite (155 OK, 2 skipped), spot checks of the validator (an edge at 1.4, a missing forecast, an unknown field and probability 1.2 are all rejected), and a read of `derive_status` and `validate_role`. Overall this is a solid contract. Fix the items below, then stop.

## must

1. **C4 / spec correction: experimental rule.** The brief was wrong and has been corrected (see BRIEF "Emerging roles" and STANDARDS C4). Experimental is tied to `status == "emerging"`, not to anchor fit.
   - Account Executive goes back to `publication: "standard"` with `fit: partial`.
   - Remove the partial-anchor rule.
   - Add the reverse check: a non-emerging role marked experimental is rejected.
   - Update the tests and fixtures.

2. **C3/C4: "agreeing" must mean the same direction.** `Signal.agrees: bool` is ambiguous. In the HR fixture, the postings signal for a rising skill even has `agrees: false`.
   - Replace `agrees` with `direction: "up" | "down" | "flat" | "presence"`. `presence` means listed in a map, with no trend.
   - `rising` requires at least one O or M signal with `direction == "up"`.
   - `fading` stays posting-driven. A lagging map that still lists a fading skill is `presence` and must not block fading.
   - Add tests:
     - a rising candidate whose only O/M signal is `presence` derives `early`;
     - the same candidate with an M `up` signal derives `rising`;
     - a rising candidate whose O/M signal is `down` derives `early`.
   - The fixtures must still reproduce the prototype's statuses.

3. **Timing must come from the source kind, not string matching.** `validate_role` infers whether a source is O*NET ratings, ESCO or BLS by casefolded substring, so "O*NET importance" with `timing: "coincident"` passes.
   - Add a closed `source_kind` enum to `Signal`: `postings`, `postings_new_phrasing`, `onet_ratings`, `onet_emerging_tasks`, `onet_hot_technologies`, `esco`, `hiring_lab`, `economic_index`, `bls_projections`, `bls_industry_matrix`, `careeronestop`.
   - Add one canonical table mapping each kind to its timing and family, matching the STANDARDS/DESIGN mapping.
   - Validation requires `timing` and `family` to equal the table. Keep `source` as the display name.
   - Test that a mismatched timing is rejected for every kind (one table-driven test).

## should
